# 核心目标文档

与作业说明 **`.cursor/goal.md`** 对照阅读；本节强调 **可交付能力**与**验收动作**。

---

## 1. 项目目标（3 小时 Demo）

在可本地运行的前提下证明：

```txt
1. 多人同房间画布协作
2. 增删改移与连线可实时同步给其他客户端
3. 基本并发下有确定策略（不出现静默丢改）
4. 框选后 AI：改写 / 扩展 / 总结
5. AI 输出流式、他人可见进行中内容
6. Ctrl+Z 撤销（含 AI 入账规则按实现约定）
7. 单客户端断线重连后状态与他人一致
```

## 2. 功能与验收锚点

### 2.1 实时多人

- ≥2 Tab 同 URL 路径中的 **同一 roomId**。  
- 一方改画布，另一方 **体感延迟一般不超过约 500ms**（局域网/本机）。

### 2.2 画布元素

| 元素 | 能力 |
|------|------|
| 文本节点 | 建、编辑、拖、删、可被框选 |
| 箭头边 | 两端接文本节点、跟随移动、删除、同步 |

### 2.3 框选与 AI

框选仅存 **前端本地/React Flow selection**，持久层以 `elements` 为准；Toolbar 读取选中节点 id → 拼凑 `content` 调后端。

三类 AI：**改写** → 更简洁正式的一则结果；**扩展** → 3 条延伸（推荐单节点内列表）；**总结** → 一句概括新节点。**Tab B 可见内容逐字增长。**

### 2.4 撤销

**最近 ~20 步**；**只撤销当前用户本地栈**；通过 **反向写 Yjs + 广播**；他人在此之后的操作不被「整体回滚抹掉」。

### 2.5 离线

断开期间 **其他 Tab 可编辑**；恢复网络后 Tab 自动追上 **最终一致**。

## 4. 最小 Demo 验收流程（手测）

### Step 1：安装与启动

```bash
npm install
npm run dev   # 或分别 dev:web / dev:server
```

### Step 2：双页同 room

```txt
例如：http://localhost:5173/board/demo
打开两个浏览器标签访问同一房间
```

### Step 3：同步

一侧创建/拖拽/删除，另一侧实时一致。

### Step 4：AI

一侧框选多节点 → 总结；两侧观察 AI 节点变长。

### Step 5：撤销

一侧 Ctrl+Z，另一侧见对应结构化结果（如节点被删）。

### Step 6：离线

断一侧网 → 另一侧继续画 → 联网后追上。
